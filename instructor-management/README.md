# Instructor management: standalone integration contract

> **Change 2026-11-19:** superseded by `chatbot/lab-management/` (Helm chart, served at `/manage/`; see `docs/lab-management.md`). This prototype is kept for reference only and is not deployed.

This is a preview and durable request journal, not a complete Milestone 2 deployment. It reads active code-owned scenario profiles and their instruction files, displays sample prompts, tests and dependencies, saves scenario selection, and records deployment or student batch requests as **blocked**. It does not execute those requests, create accounts, register models, issue credentials, approve changes, or modify existing work. Auto-approval is always off. No student count, key directory or prior selection is needed to start it.

## Deploy independently

Build from the repository root with `docker build -f instructor-management/Dockerfile -t <image> .` and publish by the operator's normal image process. Edit a copy of `deploy/management.yaml`: set the image, auth-service URL, and exact public HTTPS origin. Apply to the intended namespace, then route a dedicated HTTPS hostname through the existing gateway to `instructor-management:8080`. Do not apply this example to an existing lab without operator coordination. The service has no service-account token or Kubernetes API permissions. It requires a persistent volume that supports SQLite locking and a single replica; its Recreate strategy avoids overlapping SQLite writers. `/healthz` tests only that the process responds, not FAIG, license, scanner or model readiness.

The gateway integration is required and is **not yet supplied by this manifest**. All requests to the service except `/healthz` must be routed through gateway authentication, which must strip externally supplied `X-Lab-*` headers and inject fresh signed headers. The service independently forwards only those headers to the gateway's `/_lab/internal/admin/students` endpoint, which verifies the signature and makes a live FAIG admin API call using the gateway's server-side session. It fails closed if this check fails. The gateway-to-service and service-to-gateway paths must be restricted to trusted workloads and protected in transit where the network is untrusted. A student cannot authorize by changing a role header; signed headers are still bearer credentials during their short lifetime. This contract inherits the gateway's user-to-latest-session behavior and requires its signing key to stay private to trusted gateway/upstream components. Do not expose the management ClusterIP directly to browsers or the public internet.

The GUI expects the origin root paths `/`, `/api/*`, `/app.js`, and `/style.css` on a dedicated host. POSTs require the configured exact `Origin` and a custom header. An authenticated gateway must route all of these paths consistently, including static assets. The service does not receive FAIG passwords, admin cookies, or signing keys. Configuration must point to the gateway auth service, not the FAIG API or public login page. Gateway and service outages deny access. `/healthz` is intentionally unauthenticated for Kubernetes probes.

## Catalog and compatibility

`chatbot/scenarios/examples/catalog.json` selects active profiles. Each profile is the source for description, actions, MCP requirements, clean/attack prompts, validation cases and the instruction file. The compatibility mapping in `experiments/faig-api-lab/scenario-catalog.json` currently supplies the model alias and FAIG guard definitions; it remains a separate maintained source. The exported management view is an adapter, not yet the requested single complete authoring source. Existing `functional_test scenario-pack` and LiteLLM rendering are unchanged. `GET /api/state` includes instruction text and SHA-256 for a future adapter to compare with the deployed LiteLLM configuration; a matching hash alone does not prove runtime instruction behavior. Profiles' `schema_version` describes their schema, not a scenario revision. A stable per-scenario content revision, project definitions, expanded tool sets and migration of guard templates into the canonical source remain integration work. Do not assume unselected aliases are inaccessible via direct LiteLLM.

## State and recovery

Selection and blocked request metadata are stored in `/data/instructor.sqlite3` and its SQLite WAL files. Requests accept only explicitly defined non-secret fields; never put credentials in the journal. The journal survives container restarts with the PVC. Back up using SQLite's online backup API or a consistent volume snapshot including the WAL; restore into a stopped single replica. Deleting the PVC loses selection and journal. Requests marked blocked do not resume automatically and must not be interpreted as completed operations. Once a safe executor exists, it must reconcile remote state after timeouts before writes or retry, maintain per-step durable checkpoints and protect one-time secrets separately in appropriately scoped Kubernetes Secrets. Admin sessions are not persisted here.

## Required integration and validation

* Implement gateway routing and live-session validation for the dedicated hostname; test revoked, expired, fallback and student sessions and header spoofing. The existing gateway may retain an admin role for a session's lifetime; revalidation of current FAIG authorization must be verified against the target 8.0.2 build.
* Replace the blocked executor with separately reviewed, explicitly experimental FAIG 8.0.2 integration. Reconcile provider models without losing credentials; verify LiteLLM alias-to-instruction behavior and dependencies; publish selected chatbot content. Never silently remove or overwrite existing student objects.
* Implement student workspaces/projects, unique credentials and secure one-time handoff, dynamic chatbot identity/key access and least-privilege RBAC. Preserve and reconcile ambiguous writes, invitation and one-time-key failures across restarts. A saved selection is not a deployed scenario.
* Implement explicitly enabled, expiring auto-approval restricted to managed student workspaces and permitted object types, with actor, events and failure status. Exclude deletion, organization changes and unrelated policy bindings. Until then it remains unavailable.
* Add license/scanner, real model traffic, per-student access and isolation checks, sample prompt verdicts and measured capacity tests. Report the known Resume Deny discrepancy; no traffic or capacity claims are made here. Supported vendor compatibility is not implied.
* Coordinate Milestone 1: build and deploy the management image and PVC, configure the gateway and origin, preserve zero-student startup, provide service readiness, and pass no shared LiteLLM admin credential to student services. Normal infrastructure and quickstart remain unchanged pending integration.

Run the standalone checks with `python3 -m unittest discover -s instructor-management/tests -v`. No test invokes FAIG, AWS or Kubernetes.
